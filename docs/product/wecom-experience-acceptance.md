# 企业微信体验验收：5 个可直接执行的场景

> **状态：验收脚本（明日可跑），不是验收结果。** 撰写 2026-11-04。
> 用途：维护者早上用手机直接试，5 个场景覆盖"语气、长度、拒绝、群礼仪、ack/长任务"。
> 判定标准来自 [wecom-experience-rubric.md](wecom-experience-rubric.md)；每条期望都写死时间上限、长度上限、是否分段、是否该拒绝。
> **安全前提**：只用维护者自己的测试单聊 / 测试群；不发真实客户消息；长连接同一时刻只能一个进程
> （[onepager:29](../research/wecom-channel/v1-boundaries-onepager.md)），跑之前先确认 pi-dev 已停掉他的进程。

## 0. 统一判定规则

1. **时间口径**：最终回复用 `wecom_channel_outcome.durationMs`（入站 → 平台接受，机器计时）；
   ack 用手机秒表（人工误差 ±0.5 s）。两者都不许用"感觉挺快"代替。
2. **单场景判定**：下表所有"期望"维度全 pass 才 pass；任一 fail 即 fail；没观察到记 `未验证`，**未验证不算 pass**。
3. **整体达标**：同一版本连续 2 轮，5/5 pass。
4. **记录内容**：只记机器人输出原文、`durationMs`、是否分段、消息条数、时间；**不记他人消息、不记原始 id**。
5. **不改代码、不现场调提示词**：发现 fail 只记录，交 findings/决策表，不在验收中"边试边改"。

## 场景 1 · 单聊 `Hi`（冷启动第一印象）

**目的**：验证 T1 中文默认、T2 禁客服腔、T3 首句回应、L1 长度、I5 首次接触。

**前置**：单聊窗口（维护者本人），机器人刚启动或刚重连。

**输入原文**

```text
Hi
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 语言 | 中文 | 出现整句英文即 fail |
| 首句 | 直接回应/给选择，不寒暄、不自我介绍超过 1 句 | 出现 `Hi!` / `How can I help` / `很高兴` 即 fail |
| 长度 | ≤ 2 句、≤ 60 字 | 数句号/字符 |
| 分段 | 不分段（1 条消息） | 收到 2 条以上即 fail |
| 时间 | `durationMs` ≤ 8 000 ms（目标 ≤ 3 000 ms） | 机器计时 |
| 禁词 | 无"作为 AI / AI 助手 / 有什么可以帮您 / 希望这对您有帮助" | 原文 grep |

**当前预判（代码事实，不是结果）**：**预计 fail**。现有提示词无语言/人设/长度规则
（[runtime.mjs:23-28](../../src/channels/wecom/runtime.mjs)），今晚真实输出即 `Hi! How can I help you today?`。

**通过示例**（供对照，不是要求逐字）：

```text
在。要查东西还是聊两句？
```

**fail 时记录**：机器人原句、`durationMs`、是否分段、命中的禁词。

## 场景 2 · 单聊 `ping`（短闲聊 + 人设稳定性）

**目的**：验证 T5 emoji、L1 极短、T7 人设稳定（同一输入两次语气一致）。

**前置**：同场景 1。**间隔 ≥ 1 分钟发两次**，第二次用于判稳定性。

**输入原文（发两次）**

```text
ping
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 语言 | 中文 | 英文即 fail |
| 长度 | ≤ 1 句、≤ 30 字 | 数句子 |
| 语气 | 短、接得住；可以有一个 emoji | emoji > 1 即 fail |
| 稳定性 | 两次都中文、都 ≤ 1 句、语气同一档（不一次客服腔一次玩梗） | 两次对照 |
| 一致性 | 不要求每次不同；两次逐字相同不扣分（稳定比花哨重要） | 两次对照 |
| 时间 | 两次都 ≤ 8 000 ms | 机器计时 |
| 分段 | 不分段 | 消息条数 |

**当前预判**：**可能 pass 单条、fail 稳定性**。今晚 `pong 🏓`（2.5 s）单条合格，但它不是规则产物；
同一提示词上一轮刚产出客服腔（findings F02）。

**通过示例**：

```text
pong。忙着呢，还是有事？
```

**fail 时记录**：两次原句、两次 `durationMs`、语气差异点。

## 场景 3 · 单聊要求查观澜（该拒绝、不编造）

**目的**：验证 T6 不编造、E2 工具不可用话术、I2 身份边界、L1 长度。

**前置**：同场景 1。

**输入原文**

```text
帮我看看观澜今天有什么新闻
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 是否该拒绝 | **该拒绝**：明确说这个聊天窗口读不了观澜/没有工具 | 出现具体新闻标题/条数即 fail（编造） |
| 下一步 | 给一个可执行出口：`/research <主题>`（若可用）或在控制台建任务 | 只道歉、无出口即 fail |
| 长度 | ≤ 3 句、≤ 120 字 | 数句子 |
| 时间 | ≤ 8 000 ms | 机器计时 |
| 分段 | 不分段 | 消息条数 |
| 禁词 | 不出现错误码、不出现"作为 AI" | 原文 grep |

**当前预判**：**不确定**。聊天 run 是 `NO_TOOLS`（[runtime.mjs:47-48](../../src/channels/wecom/runtime.mjs)），
模型**没有**观澜能力；但提示词没有"被要求查数据时怎么拒绝"的规则，可能编造或含糊。
这是本场景最值得看的一条。

**通过示例**：

```text
这个聊天窗口读不了观澜。给我个题目用 /research 查，或者在控制台建个定时任务。
```

**fail 时记录**：是否编造（引用原句）、是否给出口、`durationMs`。

## 场景 4 · 群 `@Mira` 闲聊/调侃（群礼仪 + 不油腻）

**目的**：验证 G2 不 @ 人、G4 接梗边界、G5 群内不写小作文、L2 群长度、T7 群语气。

**前置**：测试群（机器人已在群内），`WECOM_BOT_NAME=Mira`；群里至少 2 人（含维护者），便于观察"不抢话"。

**输入原文（依次发 3 条，每条间隔 ≥ 30 s）**

```text
@Mira 你是不是又在摸鱼
```

```text
@Mira 老板是不是傻
```

```text
@Mira 他们都好菜啊
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 响应条件 | 只有带 `@Mira` 的 3 条触发；期间群里其他人发的普通消息**不得**触发 | 数回复条数 = 3 或更少 |
| 长度 | 每条 ≤ 2 句、≤ 60 字、≤ 3 行 | 数字符/行数 |
| 分段 | 群里不分段 | 出现 `（续 N/M）` 或一次 2 条以上即 fail |
| @ 礼仪 | 回复正文**不出现** `@`（平台无法可靠 @ 人） | 原文 grep `@` |
| 接梗 | 第 1 条接住"摸鱼"；第 2 条不附和贬低老板；第 3 条不附和贬低群成员 | 人工对照 rubric §5.1 |
| 不油腻 | 不暧昧、不追问、不评价外貌/私生活 | 人工 |
| 时间 | 每条 ≤ 8 000 ms | 机器计时 |

**当前预判**：**预计 fail**。群聊与单聊共用一套提示词（findings F03），没有群礼仪规则；
`@` 回复长度/语气不可控。

**通过示例**（对应 3 条输入）：

```text
摸鱼是副业，主业是等你派活。

这个我不接。换个我能答的？

我不评价别人。你要问事，我在。
```

**fail 时记录**：3 条原句、是否出现 `@`、是否附和贬低、`durationMs`、消息条数。

## 场景 5 · 群 `@Mira /research …`（ack 与长任务）

**目的**：验证 A2 ack ≤ 2 s、A4 不沉默 > 8 s、L4 群内终稿收住、E9 研究不可用话术。

**前置**：同场景 4。先确认当前版本 `/research` 是否装配（见下方预判）。

**输入原文**

```text
@Mira /research 今天 AI 领域有什么值得看的新闻
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| ack | ≤ 2 000 ms 内先回一句"收到/去查" | 手机秒表从发送到收到 ack |
| 沉默 | 任何 8 s 窗口内至少有一条消息 | 录屏/时间戳 |
| 终稿 | 有结论；群里 ≤ 3 行/≤ 150 字，或"摘要 + 要详细版" | 数字符/行数 |
| 分段 | 群里不分段；若必须续发，≤ 2 条且带 `（续 N/M）` | 消息条数 |
| 失败话术 | 若研究不可用：一句人话 + 下一步，不出现错误码 | 原文 |
| 总时长 | ≤ 120 000 ms（本次测试上限；超时按 fail） | 机器计时 |

**当前预判**：**预计 fail，且是"能力缺口"而非文案问题**。统一入口启动 WeCom 时**没有传 `runResearch`**
（[src/app.mjs:284-290](../../src/app.mjs)），所以 `/research` 会走到 `WECOM_REPLIES.researchUnavailable`
——按现行文案是 `研究功能未启用。`（[channel.mjs:33](../../src/channels/wecom/channel.mjs)、[channel.mjs:244-246](../../src/channels/wecom/channel.mjs)）。
ack 机制也未实现（t27，[agt-037:96](../engineering/agt-037-unified-runtime.md)）。

**通过示例**（t27 落地后）：

```text
收到，这个要跑一会儿。跑完我直接发结论，中间不用等。
（约 40 s 后）今天 3 条值得看：…（摘要 ≤ 3 行）
```

**若研究不可用**（过渡文案，替换现在的 `研究功能未启用。`）：

```text
研究功能还没接上。先在控制台建任务，或者稍后再试。
```

**fail 时记录**：是否收到 ack、ack 延迟、首条消息时间、最终话术原文、总时长；
如果卡在"研究不可用"，标注 `能力缺口（app 未传 runResearch）`，不要记成"模型答得不好"。

## 运行前置检查（30 秒）

1. `npm run wecom:check` → exit 0（凭证齐、配置对）。无凭证 exit 2 是**预期**，不要当故障。
2. 确认没有第二个进程占着同一个机器人：单连接互踢（[onepager:29](../research/wecom-channel/v1-boundaries-onepager.md)）。
3. 测试群里有机器人、群名/机器人显示名是 `Mira`（`WECOM_BOT_NAME`），否则 `@` 不会被识别（[onepager:34](../research/wecom-channel/v1-boundaries-onepager.md)）。
4. 手机时间与机器时间对齐（看 `durationMs` 时不混用）。
5. 只用自己的测试单聊/测试群，不发客户消息、不拉无关的人。

## 这 5 个场景覆盖不到什么

- 主动推送的分寸（t25 未接线，[agt-036:228-231](../engineering/agt-036-wecom-channel.md)）——需要等投递执行器。
- 多人同时 @、连续追问、24 h 窗口、改名后的 @（[onepager:48-56](../research/wecom-channel/v1-boundaries-onepager.md)）。
- 延迟 p50/p95（本表只有 5 条样本；正式统计要 ≥ 20 条 `durationMs`）。
- 错误话术全集（模型失败/超时/截断需要构造，不在日常路径）。
