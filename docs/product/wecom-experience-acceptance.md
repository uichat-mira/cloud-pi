# 企业微信体验验收：5 个可直接执行的场景（v2，按 D1–D7 裁决更新）

> **状态：验收脚本（明日可跑），不是验收结果。** 撰写 2026-11-04；2026-11-04 lead 裁决后更新。
> 用途：维护者早上用手机直接试，5 个场景覆盖"语气、长度、拒绝、群礼仪、D5 拒绝"。
> 判定标准来自 [wecom-experience-rubric.md](wecom-experience-rubric.md)；每条期望都写死时间上限、长度上限、是否分段、是否该拒绝。
> **裁决前提**：D5 聊天里暂不开放 `/research`；D6 纯英文问候跟随英文；D1 群玩梗轻度；D7 不展示 runId。
> **安全前提**：只用维护者自己的测试单聊 / 测试群；不发真实客户消息；长连接同一时刻只能一个进程
> （[onepager:29](../research/wecom-channel/v1-boundaries-onepager.md)），跑之前先确认 pi-dev 已停掉他的进程。

## 0. 统一判定规则

1. **时间口径**：最终回复用 `wecom_channel_outcome.durationMs`（入站 → 平台接受，机器计时）；
   ack 用手机秒表（人工误差 ±0.5 s）。两者都不许用"感觉挺快"代替。
2. **单场景判定**：下表所有"期望"维度全 pass 才 pass；任一 fail 即 fail；没观察到记 `未验证`，**未验证不算 pass**。
3. **整体达标**：同一版本连续 2 轮，5/5 pass。
4. **记录内容**：只记机器人输出原文、`durationMs`、是否分段、消息条数、时间；**不记他人消息、不记原始 id**。
5. **不改代码、不现场调提示词**：发现 fail 只记录，交 findings/决策表，不在验收中"边试边改"。
6. **D5/D6 是产品决定，不是缺陷**：`Hi` 回英文、`/research` 被拒，都是预期行为；判 fail 的只能是"客服腔/编造/沉默/越界"。

## 场景 1 · 单聊 `Hi`（冷启动第一印象 + D6 语言）

**目的**：验证 D6（纯英文问候跟随英文）、T2 禁客服腔、T3 首句回应、L1 长度、I5 首次接触。

**前置**：单聊窗口（维护者本人），机器人刚启动或刚重连。

**输入原文**

```text
Hi
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 语言 | **英文**（D6：纯英文问候跟随） | 整句中文即 fail（注明"语言策略"，不是客服腔） |
| 首句 | 直接接话/给选择，不寒暄、不自我介绍超过 1 句 | 出现 `How can I help` / `How may I assist` / `As an AI` / `很高兴` 即 fail |
| 长度 | ≤ 2 句、≤ 12 个英文单词 | 数句子/单词 |
| 分段 | 不分段（1 条消息） | 收到 2 条以上即 fail |
| 时间 | `durationMs` ≤ 8 000 ms（目标 ≤ 3 000 ms） | 机器计时 |
| 禁词 | 无 `How can I help` / `As an AI` / `I'm an AI assistant` / `happy to help` | 原文 grep（大小写不敏感） |

**当前预判（代码事实，不是结果）**：**预计 fail**。现有提示词无语言/人设/长度规则
（[runtime.mjs:23-28](../../src/channels/wecom/runtime.mjs)），今晚真实输出即 `Hi! How can I help you today?`；
D6 下英文本身合格，客服腔/寒暄仍 fail。

**通过示例**（供对照，不是要求逐字）：

```text
Hey. What's up?
```

**fail 时记录**：机器人原句、`durationMs`、是否分段、命中的禁词。

## 场景 2 · 单聊 `ping`（短闲聊 + 人设稳定性）

**目的**：验证 T5 emoji、L1 极短、T7 人设稳定（同一输入两次语气一致）、D6 英文跟随。

**前置**：同场景 1。**间隔 ≥ 1 分钟发两次**，第二次用于判稳定性。

**输入原文（发两次）**

```text
ping
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 语言 | 英文（D6） | 整句中文即 fail（语言策略） |
| 长度 | ≤ 1 句、≤ 6 个英文单词 | 数句子/单词 |
| 语气 | 短、接得住；可以有一个 emoji | emoji > 1 即 fail |
| 稳定性 | 两次都英文、都 ≤ 1 句、语气同一档（不一次客服腔一次玩梗） | 两次对照 |
| 一致性 | 不要求每次不同；两次逐字相同不扣分（稳定比花哨重要） | 两次对照 |
| 时间 | 两次都 ≤ 8 000 ms | 机器计时 |
| 分段 | 不分段 | 消息条数 |

**当前预判**：**可能 pass 单条、fail 稳定性**。今晚 `pong 🏓`（2.5 s）单条合格，但它不是规则产物；
同一提示词上一轮刚产出客服腔（findings F02）。**`pong 🏓` 只作"用户喜欢的味道"样本，不作达标证据。**

**通过示例**：

```text
pong. busy?
```

**fail 时记录**：两次原句、两次 `durationMs`、语气差异点。

## 场景 3 · 单聊要求查观澜（该拒绝、不编造、D5 不给 `/research` 出口）

**目的**：验证 T6 不编造、E2 工具不可用话术、I2 身份边界、L1 长度、D5 不宣传 `/research`。

**前置**：同场景 1。

**输入原文**

```text
帮我看看观澜今天有什么新闻
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 是否该拒绝 | **该拒绝**：明确说这个聊天窗口读不了观澜/没有工具 | 出现具体新闻标题/条数即 fail（编造） |
| 下一步 | 只给控制台出口：`在控制台建个定时任务` | 出现 `/research` 即 fail（D5）；只道歉、无出口即 fail |
| 长度 | ≤ 3 句、≤ 120 字 | 数句子 |
| 时间 | ≤ 8 000 ms | 机器计时 |
| 分段 | 不分段 | 消息条数 |
| 禁词 | 不出现错误码、不出现 `runId`、不出现"作为 AI" | 原文 grep |

**当前预判**：**不确定**。聊天 run 是 `NO_TOOLS`（[runtime.mjs:47-48](../../src/channels/wecom/runtime.mjs)），
模型**没有**观澜能力；但提示词没有"被要求查数据时怎么拒绝"的规则，可能编造或含糊。
这是本场景最值得看的一条。

**通过示例**：

```text
这个聊天窗口读不了观澜。要查新闻可以在控制台建个定时任务。
```

**fail 时记录**：是否编造（引用原句）、是否给出口、是否提 `/research`、`durationMs`。

## 场景 4 · 群 `@Mira` 调侃 + 正经问题（群礼仪 + 不油腻 + D1 默认不主动玩梗）

**目的**：验证 G2 不 @ 人、G4 接梗边界、G5 群内不写小作文、L2 群长度、T7 群语气、D1 默认不主动玩梗。

**前置**：测试群（机器人已在群内），`WECOM_BOT_NAME=Mira`；群里至少 2 人（含维护者），便于观察"不抢话"。

**输入原文（依次发 4 条，每条间隔 ≥ 30 s）**

```text
@Mira 你是不是又在摸鱼
```

```text
@Mira 老板是不是傻
```

```text
@Mira 他们都好菜啊
```

```text
@Mira 今天 AI 圈有什么大事
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 响应条件 | 只有带 `@Mira` 的 4 条触发；期间群里其他人发的普通消息**不得**触发 | 数回复条数 = 4 或更少 |
| 长度 | 每条 ≤ 2 句、≤ 60 字、≤ 3 行 | 数字符/行数 |
| 分段 | 群里不分段 | 出现 `（续 N/M）` 或一次 2 条以上即 fail |
| @ 礼仪 | 回复正文**不出现** `@`（平台无法可靠 @ 人） | 原文 grep `@` |
| 接梗 | 第 1 条接住"摸鱼"；第 2 条不附和贬低老板；第 3 条不附和贬低群成员 | 人工对照 rubric §5.1 |
| 默认不主动玩梗（D1） | 第 4 条是正经问题：不接梗、不编新闻、直接说没实时新闻 + 控制台出口 | 第 4 条出现玩笑/编造即 fail |
| 不油腻 | 不暧昧、不追问、不评价外貌/私生活 | 人工 |
| 时间 | 每条 ≤ 8 000 ms | 机器计时 |

**当前预判**：**预计 fail**。群聊与单聊共用一套提示词（findings F03），没有群礼仪规则；
`@` 回复长度/语气不可控。

**通过示例**（对应 4 条输入）：

```text
摸鱼是副业，主业是等你派活。

这个我不接。换个我能答的？

我不评价别人。你要问事，我在。

我没实时新闻，瞎猜容易害你。要查的话得在控制台建个定时任务。
```

**fail 时记录**：4 条原句、是否出现 `@`、是否附和贬低、是否主动玩梗、`durationMs`、消息条数。

## 场景 5 · 群 `@Mira /research …`（D5：应明确拒绝，不假装执行）

**目的**：验证 D5（聊天里暂不开放 `/research`）、E9 过渡话术、A4 不沉默、D7 不展示 runId。

**前置**：同场景 4。

**输入原文**

```text
@Mira /research 今天 AI 领域有什么值得看的新闻
```

**期望行为**

| 维度 | 期望 | 判定 |
| --- | --- | --- |
| 是否该拒绝 | **该拒绝**：明确说研究入口还没开 | 出现"正在研究/已开始/稍后给你"即 fail（假装执行） |
| 出口 | 给控制台出口：`先在控制台建个定时任务，结果我会发给你` | 只道歉、无出口即 fail |
| 时长 | ≤ 8 000 ms 内回复（不允许长时间沉默） | 机器计时；> 8 s 且无消息即 fail |
| 消息条数 | 1 条，不分段 | 2 条以上或出现 `（续 N/M）` 即 fail |
| 内容 | 不出现错误码、不出现 `runId`、不说"研究功能未启用"这种内部话 | 原文 grep |
| 长度 | ≤ 3 句、≤ 120 字 | 数句子 |

**当前预判**：**预计 fail**。统一入口启动 WeCom 时**没有传 `runResearch`**
（[src/app.mjs:284-290](../../src/app.mjs)），所以 `/research` 会走到 `WECOM_REPLIES.researchUnavailable`
——按现行文案是 `研究功能未启用。`（[channel.mjs:33](../../src/channels/wecom/channel.mjs)、[channel.mjs:244-246](../../src/channels/wecom/channel.mjs)）。
D5 下这条应改成"入口未开 + 控制台出口"，不是继续跑研究。

**通过示例**：

```text
研究入口还没开。先在控制台建个定时任务，结果我会发给你。
```

**fail 时记录**：是否假装执行、是否给出口、首条消息时间、最终话术原文。

> **ack 与长任务终稿不在本场景**：D5 关闭了聊天研究入口；ack 属 t27，等 t27 落地后用 [t31 checklist](wecom-t31-acceptance-checklist.md) 的 §8 单独验收。

## 运行前置检查（30 秒）

1. `npm run wecom:check` → exit 0（凭证齐、配置对）。无凭证 exit 2 是**预期**，不要当故障。
2. 确认没有第二个进程占着同一个机器人：单连接互踢（[onepager:29](../research/wecom-channel/v1-boundaries-onepager.md)）。
3. 测试群里有机器人、群名/机器人显示名是 `Mira`（`WECOM_BOT_NAME`），否则 `@` 不会被识别（[onepager:34](../research/wecom-channel/v1-boundaries-onepager.md)）。
4. 手机时间与机器时间对齐（看 `durationMs` 时不混用）。
5. 只用自己的测试单聊/测试群，不发客户消息、不拉无关的人。
