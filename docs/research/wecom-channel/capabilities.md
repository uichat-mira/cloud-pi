# 企业微信接入模型与 Channel 能力边界

> 访问日期 2026-11-04。每条结论带证据标签；`[未验证]` 一律不得当作实现依据。

## 1. 五种"机器人"接入形态的真实边界

| 形态 | 谁在用 | 能否收消息 | 能否主动推 | 传输 | 关键限制 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| **群机器人 Webhook（传统）** | 运维告警、CI 通知 | **不能**（只出不进） | 只能推给它被加入的群 | 一个 webhook URL + HTTP POST | 无会话、无单聊、无事件回调、无身份；官方现行导航把该能力归入「消息推送（原"群机器人"）」 | `[文档]` 61964 明确"与传统应用/群机器人不同"；导航节点 101050/101094 存在但**正文不可抓取**（`doc_id=0`），故具体字段/限流标 `[未验证]` |
| **企业内部自建应用** | 企业内部系统集成 | 能（需配置接收消息 URL + 加解密） | 能（`access_token` + 应用消息 API） | 自建 HTTP 服务 + 公网回调 | 要 `access_token`（corpid+secret 换取）、IP 白名单/可信域名、消息加解密；身份是成员 userid；**不是** AI 对话通道 | `[文档]` 10167（发送应用消息）、61328（`access_token` 与 `open_userid→userid`）、10785（频控） |
| **智能机器人 · 普通模式** | 不想写代码的企业 | 内置模型处理 | 内置能力 | 无开发者接入 | 无法自定义 Agent；仅用于确认"智能机器人 ≠ 自建应用" | `[文档]` 62132 |
| **智能机器人 · API 模式 · URL 回调** | 有公网服务的团队 | 能（加密回调） | 能（`response_url`，一次性 1 h） | 公网 HTTPS | 需公网 IP、Token/EncodingAESKey、签名与解密、5 s 响应窗口、最多 3 条消息并发 | `[文档]` 62161–62166 |
| **智能机器人 · API 模式 · 长连接** | 内网/无公网 IP 团队（**本项目**） | 能（明文 WS 帧） | 能（`aibot_send_msg`，需先有用户消息） | WSS 长连接 | 单机器人**仅 1 条**连接；需心跳与重连；无加解密 | `[文档]` 62154–62160 |

> 结论：**本项目只需要第 5 种**。传统 Webhook 不能满足"收消息"；自建应用是另一套身份与凭证体系
> （`access_token` + 可见范围），会引入本项目不需要的权限面，且没有 AI 对话语义。
> 唯一需要自建应用的地方是 §5 的 `open_userid → userid` 转换——那是一个**按需调用**的辅助 API，
> 不是第二条 Channel。

## 2. 收消息

`[文档]` 62155（长连接）：

- 命令：`aibot_msg_callback`；`headers.req_id` **必须透传**用于回复。
- 公共字段：`msgid`（排重）、`aibotid`、`chatid`（**仅群聊返回**）、`chattype`（`single`/`group`）、
  `from.userid`、`msgtype`、`compat_info`（存在即表示非普通用户消息：`ai_assistant` / `channel`）。
- 支持类型：`text`（含 `quote` 引用）、`image`、`mixed`（图文混排，`msg_item[]`）、`voice`（转文本）、
  `file`、`video`。
- 触发场景（`[文档]` 62163，URL 回调节点同源）：群里 **@ 机器人** 或单聊发文本/图文/引用；
  图片/语音/文件/视频**仅单聊**支持。

`[未验证]`：
- 群聊中**未 @ 机器人**的消息是否 100% 不推送（文档只列了 @ 场景，未写"绝不推送"）。
- 机器人被移出群、群解散时是否有事件。
- `compat_info` 之外的系统消息（如应用转发的网页消息）——`[社区]` Issue #18 报告"不支持应用转发的网页消息"。

## 3. 回复与流式

`[文档]` 62157：

| 场景 | 命令 | 时限 |
| --- | --- | --- |
| 进入会话事件 | `aibot_respond_welcome_msg` | 事件后 **5 s** 内，超时无法发送 |
| 消息回调 | `aibot_respond_msg`（`msgtype: stream`） | 收到回调后 **24 h** 内可向该会话回复；流式从首帧起 **10 min** 内必须 `finish=true`，否则自动结束 |
| 模板卡片事件 | `aibot_respond_update_msg` | **5 s** 内 |

- 流式 `content` 为**全量**内容（非增量），**≤20480 字节**（UTF-8），支持 Markdown；
  含 `<think></think>` 时客户端展示思考过程。
- 同一 `req_id` 的多次刷新共用同一个 `stream.id`；`finish=true` 后不可再更新。
- 长连接**没有**"流式刷新回调"，节奏完全由开发者控制（这是相对 URL 回调的核心优势）。
- `[未验证]` 流式首帧到首字节的最小时限、两次刷新之间的最小间隔（文档未写）。

## 4. 主动推送（本项目 Scheduler 交付的关键）

`[文档]` 62158：

```json
{"cmd":"aibot_send_msg","headers":{"req_id":"..."},
 "body":{"chatid":"...","chat_type":1,"msgtype":"markdown","markdown":{"content":"..."}}}
```

- `chatid`：**单聊填 userid，群聊填回调里的 chatid**；`chat_type`：`1` 单聊 / `2` 群聊 / 0 或缺省
  自动兼容（**文档注明缺省时优先按群聊处理**）。
- 支持类型：`markdown`、`template_card`、`file`、`image`、`voice`、`video`（媒体需先上传取 `media_id`）。
- **前置条件（硬约束）**：用户必须**先在会话里给机器人发过消息**，之后机器人才可能主动推送给该会话。
  `[社区]` Issue #23 独立确认："如果用户没有主动和 agent 互动过，sendMessage 报错"，并称这让纯主动
  场景"完全瘫痪"。
- 频率：回复与主动推送**合并计算**，单个会话 **30 条/分钟、1000 条/小时**。
- `[未验证]` "发过一次消息"的窗口有多长（永久？按会话活跃度？），以及群聊场景是否也要求群内曾有人 @ 过。
- `[未验证]` 主动推送的 `req_id` 回执是否也走 5 s 超时（SDK 是同一套 pending 机制，推论是"是"）。

## 5. 身份与会话标识

| 字段 | 含义 | 约束 | 证据 |
| --- | --- | --- | --- |
| `from.userid` | 消息发送者 | 机器人**创建者是超级管理员 → 明文 userid**；否则是**企业主体下的加密 userid（open_userid）** | `[文档]` 62155 |
| `chatid` | 群会话 id | 单聊**不返回**；主动推送单聊时用 userid 当 chatid | `[文档]` 62155 / 62158 |
| `chattype` | `single` / `group` | —— | `[文档]` 62155 |
| `msgid` | 回调唯一标志 | 用于排重（网络原因可能重复回调） | `[文档]` 62155 |
| `aibotid` | 机器人 id | 与 BotID 对应 | `[文档]` 62155 |

**群成员身份**：长连接回调**只给触发者** `from.userid`，**没有**群成员列表、没有"@ 了谁"的结构化字段。
`[文档]` 62163 的文本示例把 @ 直接写进正文（`"@RobotA hello robot"`），`[SDK源码]` 的
`types/message.ts` 也没有 `mentions`。因此：

- 判定"是否 @ 了本机器人"只能靠正文解析（风险见 `[社区]` #15 控制字符破坏 JSON、#4 群里希望免 @）。
- 需要群成员身份时必须另走通讯录 API，属于**新的权限面**，本卡不建议做。

**open_userid 转换**（若机器人不是超管创建）：`[文档]` 61328，需要
`POST /cgi-bin/batch/openuserid_to_userid?access_token=...`，而 `access_token` 来自**自建应用**
（corpid + secret），且"成员需在该应用可见范围内"，单次 ≤1000 个。这会把"一个机器人"变成
"机器人 + 自建应用 + 可见范围维护"，是显著的成本与权限扩张。

## 6. 媒体、卡片

| 能力 | 事实 | 证据 |
| --- | --- | --- |
| 上传临时素材 | 三步：`aibot_upload_media_init` → `..._chunk` → `..._finish`；会话 30 min；分片 ≤4 MB、≤100 片；`media_id` **3 天**有效；单机器人 30 次/分、1000 次/时 | `[文档]` 62159 |
| 大小上限 | 图片 10 MB、语音 2 MB、视频 10 MB、普通文件 20 MB；图片 png/jpg/gif、语音 amr、视频 mp4 | `[文档]` 62159 |
| 回调媒体解密 | 长连接每链接独立 `aeskey`（32 字节 UTF-8，直接作密钥，IV 取前 16 字节，AES-256-CBC + PKCS#7）；URL 回调用统一 `EncodingAESKey` | `[文档]` 62155 / 62163 |
| 下载链接 | 5 分钟内有效，已加密 | `[SDK源码]` `types/message.ts` |
| 模板卡片 | 5 种类型（`text_notice`/`news_notice`/`button_interaction`/`vote_interaction`/`multiple_interaction`）；点击事件 5 s 内响应；`task_id` 用于更新 | `[文档]` 62160 / 62156 / 62165 |
| 卡片事件形状 | `[社区]` Issue #22 报告 `TemplateCardEventData` 与运行时实际形状不一致 | `[社区]` |

## 7. 加解密与凭证形态

| 形态 | 凭证 | 加密 | 轮换 |
| --- | --- | --- | --- |
| 长连接 | `BotID` + `Secret`（长连接专用，**与** URL 回调的 Token/EncodingAESKey **不同**） | 无（WSS 传输层加密，业务明文） | 控制台重置 Secret（`[待界面确认]` 具体入口）；重置即旧值失效 |
| URL 回调 | `Token` + `EncodingAESKey` | 有：签名 `msg_signature` + AES-CBC 消息体；`receiveid` 传空字符串 | 同上 |

`[文档]` 62131 / 62132 / 62162 / 57141（旧版明确 receiveid 为空）。

## 8. 管理员权限与可见范围

- API 模式必须在控制台开启，凭证在机器人详情页获取（`[文档]` 62131）。
- 「可使用权限」是 CLI/MCP 反向调用企业数据（文档/日程/会议/待办）的独立授权，**不是**消息收发前置；
  文档能力授权 **7 天**有效（`[文档]` 62131 / 60967）。
- **可见范围 / 成员可用性设置：文档未写** → `[待界面确认]`（见 `admin-setup.md` §5）。
- `[社区]` Issue #17 报告"除了管理员其他人都不能接收到消息"——这是**可见范围/成员可用性**问题的
  典型症状，但社区帖并非平台合同，需在 POC 中用普通成员账号实测。
