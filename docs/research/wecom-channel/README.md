# 企业微信智能机器人 Channel 研究（AGT-031 / Issue #13）

> 分支 `docs/agt-031-wecom-research`　｜　Draft PR：https://github.com/uichat-mira/cloud-pi/pull/23
> 资料访问日期：**2026-11-04**　｜　本目录只做研究，**不修改产品代码、不部署、不改企业微信配置**。

## 0. 结论（先看这里）

### 总判断：**有条件推荐**

企业微信智能机器人（API 模式 + WebSocket 长连接）可以作为 Cloud Pi 的第二个 IM Channel，
但必须接受四条产品/工程条件。它不是"飞书换皮"，也不是"传统群机器人升级版"。

**推荐理由（有证据）**
1. 官方原生支持长连接，本机（家庭网络、无公网入口）实测可直连，**不需要公网 IP / 域名 / 备案 / 隧道**。
2. 原生支持**流式回复**（`stream`，全量 content，10 分钟），比当前飞书 Adapter 的纯文本回复更强。
3. 官方 Node SDK 是 MIT、只依赖 3 个包、**不含任何 Agent Runtime**，可像飞书那样薄复用。
4. 消息/事件/身份字段与现有 Channel 需求同构，`createAgentRuntime().run()` 不需要改。

**条件（缺一不可）**
| # | 条件 | 不满足的后果 |
| --- | --- | --- |
| C1 | 维护者创建机器人（API 模式 + 长连接）并交付 `BotID`/`Secret` | 无法 Live，只能停在离线 smoke |
| C2 | 主动推送只面向**已有入站会话**（用户/群先给机器人发过消息） | Scheduler 冷启动投递不可用；这是平台硬约束，不是实现缺陷 |
| C3 | `userid`/`open_userid` **不**映射为 Cloud Account 身份；要映射必须另立绑定卡 | 越权、隐私与审计风险 |
| C4 | 部署必须**单连接/主备**，不能多实例同时连 | 新连接踢旧连接，消息随机丢失 |

### 分项结论

| 问题 | 结论 |
| --- | --- |
| 最适合的接入模式 | **智能机器人 API 模式 + WebSocket 长连接**。传统群机器人 Webhook 不能收消息；自建应用是另一套 `access_token` + 可见范围体系，会扩大权限面且无 AI 对话语义；URL 回调用不上（本机无公网入口，且需要 Token/AESKey/签名/1 s 验证/5 s 响应） |
| 是否支持长连接 | **支持**。端点 `wss://openws.work.weixin.qq.com`；旧文档端点已 404（`transport.md`） |
| 作为"聊天 Channel" | **推荐**。单聊/群 @/流式/文本齐全；但 @ 只能靠文本解析，群成员身份拿不到 |
| 作为"研究报告主动投递 Channel" | **有条件推荐**。能推 markdown（≤20480 字节/段）、有频控，但**必须先有入站消息**；因此只能投给"已经和机器人说过话"的人/群 |
| 是否抽极薄 Channel Port | **不抽通用 Channel Port**；维持两个独立 adapter，只固定三个最小共享合同（destination / 结果 / 幂等键）（`feishu-comparison.md` §2） |
| Live 是否执行 | **未执行**。维护者尚未创建机器人、无 BotID/Secret。本目录不含任何"真实收发通过"的声明 |

## 5. 未解决问题（需要后续卡/维护者裁决）

1. **可见范围与成员可用性**：现行官方文档未写；需要界面确认 + 普通成员实测（`admin-setup.md` §5）。
2. **"曾发过消息"的有效期**：官方未写，决定 Scheduler 能否长期投递给同一 destination。
3. **群聊主动推送是否也要求"群里曾有人 @ 过"**：未验证。
4. **事件重投窗口**：官方未公布；去重策略只能按保守假设设计。
5. **错误码表**：长连接 `errcode` 没有公开清单（如 853000 是实测得到），重试分类缺依据。
6. **`chat_type` 缺失**：SDK 不暴露，单聊主动推送需自拼帧——是否向上游提 issue/补丁待定。
7. **多实例/主备**：官方建议主备但未给机制；需要设计"谁持有连接"的选主方案。
8. **open_userid 转换**：若机器人由普通管理员创建，是否引入自建应用属产品/安全决策。
9. **`msg_item` 与卡片**：SDK 与文档不一致，是否使用需 Live 验证。
10. **POC 卡编号**：本目录草案不占号，等维护者分配（勿用 AGT-036/037/038）。

## 6. 一句话给维护者

**建议开实施卡（POC）并先给凭证**：链路技术上可行、无公网依赖、SDK 可复用；
但请同时接受"主动投递只能给已有会话"和"userid 不做账号映射"这两条产品约束。
