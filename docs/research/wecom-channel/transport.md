# 传输形态结论：长连接可用，且是本机唯一可行形态

> 回答 lead 的第 2 项（t6 硬前提）。访问日期 2026-11-04。
> 结论先行：**企业微信智能机器人官方支持 WebSocket 长连接，本机（Windows 家庭网络、无公网入口）
> 已实测可直连该端点，不需要公网 HTTPS、可信域名或隧道。** URL 回调形态同样存在，但本机不具备
> 落地条件，仅作为备选记录。

## 1. 两种 API 模式

`[文档]` 62132「基本概念」：智能机器人有「普通模式」（企业微信内置能力直接对话）与「API 模式」
（开发者自定义处理）。只有 API 模式开放消息收发/CLI/MCP。API 模式下连接方式二选一：

| | 长连接（WebSocket） | URL 回调（Webhook） |
| --- | --- | --- |
| 推送方式 | 已建立的 WS 连接实时推送 | 企业微信向配置的 URL 发 HTTP POST |
| 加解密 | **无需**，明文 JSON | **需要** Token + EncodingAESKey 签名与解密 |
| 流式消息 | 开发者主动推送更新 | 企业微信轮询回调 URL 取最新内容 |
| 部署要求 | 可内网，**无需公网 IP** | 需公网可访问的 HTTPS URL |
| 高可用 | **同一机器人仅允许一个有效连接** | 支持多实例负载均衡 |
| 凭证 | `BotID` + `Secret` | `Token` + `EncodingAESKey` |

来源：`[文档]` 62132、62154（概述）、62131（开发前必读）。

## 2. 长连接的硬事实（可直接写进实现）

| 事实 | 值 | 证据 |
| --- | --- | --- |
| 端点 | `wss://openws.work.weixin.qq.com` | `[文档]` 62154 + `[SDK源码]` `src/ws.ts:7` |
| 连接建立 | WS 握手成功后发 `aibot_subscribe`，body `{bot_id, secret}` | `[文档]` 62154 |
| 认证失败错误码 | `853000`（invalid bot_id or secret） | `[实验]` 见 §3 |
| 心跳 | `{"cmd":"ping","headers":{"req_id":...}}`，建议每 30 s | `[文档]` 62154；`[SDK源码]` 默认 `heartbeatInterval 30000`、连续 2 次无 pong 判定断线 |
| 连接数量 | 每个机器人**同时只能有 1 条有效连接**；新连接订阅成功后踢掉旧连接，旧连接收到 `disconnected_event` | `[文档]` 62154 / 62156 |
| 高可用要求 | 官方建议**主备切换**，禁止多实例同时连 | `[文档]` 62154 |
| 重连 | 需开发者实现；`disconnected_event` 后由业务决定是否重连 | `[文档]` 62154 / 62156；`[SDK源码]` 指数退避 1s→2s→4s→…→30s，默认最多 10 次 |
| 可信 IP / 域名 / 备案 | 长连接形态**官方未要求**任何一项；凭证是 BotID + Secret | `[文档]` 62154（"可内网部署，无需公网 IP"）；`[未验证]` 是否另有企业侧出网白名单，官方未写 |
| ACK 语义 | 每个请求需服务端回执 `{headers.req_id, errcode, errmsg}`；SDK 硬编码 5 s 回执超时 | `[文档]` 62154；`[SDK源码]` `ws.ts` `replyAckTimeout = 5000` |
| 传输加密 | WSS（TLS）；消息体明文，SDK 支持 `wsOptions`（`ca`/`cert`/`key`/`rejectUnauthorized`） | `[文档]` 62154；`[SDK源码]` `types/config.ts` |

## 3. 本机实测（2026-11-04，无真实凭证）

环境：Windows 开发机，Node `v24.9.0`，`@wecom/aibot-node-sdk@1.0.7`，占位凭证
（`PLACEHOLDER_BOT_ID` / `PLACEHOLDER_SECRET`）。脚本只做"连接 + 订阅 + 断链"，不发送消息。

| 检查 | 结果 |
| --- | --- |
| DNS | `openws.work.weixin.qq.com` → 解析成功 |
| TCP 443 直连（无代理） | 可达 |
| WS 握手 | 155 ms 内触发 `connected` |
| 订阅结果 | 服务端拒绝：`Authentication failed: invalid bot_id or secret ... (code: 853000)` |
| 失败后的行为 | 自动重连 2 次（≤2 s），随后 `Max auth failure attempts exceeded (2)`，连接关闭 |
| 旧文档端点 `wss://open.work.weixin.qq.com/ws/aibot` | WS 握手 `HTTP 404`，重连耗尽 |

**这说明**：端点与协议路径真实存在且本机可达；占位凭证被正确拒绝。**不说明**真实凭证可用——
Live 认证/收发仍未执行，等维护者提供 BotID/Secret（见 `poc-card.md`）。

## 4. URL 回调形态的实际要求（若将来需要）

`[文档]` 62161–62166、62163：

1. **公网 HTTPS** URL：企业微信需从公网 POST 回调。`[未验证]` 是否强制 443/证书链要求，文档未逐条写明。
2. **URL 验证**：保存配置时企业微信发 `GET ?msg_signature&timestamp&nonce&echostr`，需 **1 秒内**
   返回解密后的明文（不加引号、无 BOM、无换行）。
3. **签名与解密**：`msg_signature = SHA1(sort(token, timestamp, nonce, encrypt))`；正文 AES-CBC 解密，
   `receiveid` 传空字符串（`[文档]` 57141 旧版明确；现行 62162 为通用方案）。
4. **响应时限**：模板卡片事件"五秒内收不到响应会断掉连接并丢弃该回调"（`[文档]` 62156）；
   被动回复必须在响应包内返回。
5. **异步回复**：回调带 `response_url`，**只能调用一次、有效期 1 小时**（`[文档]` 62166）。
6. **并发**：同一机器人最多同时 3 条消息交互中（`[文档]` 62163）。
7. **凭证轮换**：`Token` / `EncodingAESKey` 可在控制台重置；重置即旧值失效——轮换窗口与灰度
   `[未验证]`。

## 5. 若必须走回调：三种选项的代价

本机是家庭网络、无公网入口。**当前不需要**这些选项（长连接已可用），仅在被明确要求"必须回调"
时供裁决：

| 选项 | 做法 | 代价 / 风险 |
| --- | --- | --- |
| A. 自建隧道 | cloudflared / frp / ngrok 把本机端口映射成公网 HTTPS | 依赖第三方/自建中转可用性；URL 随隧道域名变化，每次变更需回控制台改配置并重验；家庭宽带上行与 NAT 抖动会导致 5 s 响应窗口超时；安全面扩大（公网暴露服务）；**不保证**企业微信侧对隧道域名无额外要求 |
| B. 云函数中转 | 云函数接收回调、验签解密、转发到本机长轮询/队列 | 需要云账号、部署与运维、出网与密钥托管；引入第二跳延迟与新的信任边界；等于给一个本可用长连接解决的问题新增基础设施 |
| C. 放弃回调形态 | 只用长连接 | 失去"多实例负载均衡"；单连接是官方限制，需主备切换；无公网依赖 |

**建议**：选 C。长连接在能力上覆盖本项目的收发需求，且是官方推荐给"内网/无公网 IP/高实时性"的
场景（`[文档]` 62154）。只有当需要多实例水平扩展时，才重新评估 URL 回调（`[文档]` 62132 明确
URL 回调支持多实例负载均衡）。

## 6. 对 t6 的一句话结论

传输形态 = **WebSocket 长连接 + `BotID`/`Secret` 订阅 + 30 s 心跳 + 单连接（主备）+ 应用层重连**；
本机无需任何公网改造即可开发；多实例部署必须显式设计主备，不能两个进程同时连。
