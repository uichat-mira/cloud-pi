# 企业微信智能机器人 · 管理员控制台配置清单

> 面向：拥有企业微信**管理员权限**、但**尚未创建智能机器人**的维护者。
> 目标：用最少步骤创建一个「API 模式 + 长连接」的智能机器人，并把 `BotID` / `Secret` 安全交付给工程侧。
> 依据：`[文档]` 62131（开发前必读）、62154（长连接概述）、62132（基本概念）、58634（客户端版本 FAQ）；
> 访问日期 **2026-11-04**。
>
> 标注约定：**[已确认]** = 官方文档明确写了；**[待界面确认]** = 文档未写具体控件/文案，请以实际界面为准，
> 不要照抄本清单里的按钮名称；**[安全]** = 工程侧要求。

## 0. 前置条件

| # | 检查 | 状态 |
| --- | --- | --- |
| 0.1 | 你的账号是企业微信**管理员**（能进入管理后台「工作台」配置应用/机器人） | [已确认] 前提 |
| 0.2 | 企业微信客户端版本 **≥ 4.1.32**（否则通讯录里看不到智能机器人） | [已确认] 58634 |
| 0.3 | 客户端与电脑版均已更新到最新版 | [已确认] 58634 |
| 0.4 | 决定机器人**由谁创建**：`from.userid` 是否明文取决于"机器人创建者是否企业超级管理员" | [已确认] 62155；见 §3 |

> §0.4 很关键：普通管理员创建的机器人，回调里的 `from.userid` 是**加密的 open_userid**，
> 需要额外的自建应用 `access_token` 才能换成明文 userid（`[文档]` 61328）。若希望首版拿到的就是
> 明文 userid，由**企业超级管理员**创建并持有该机器人最省事。这是产品/安全决策，不是纯配置问题。

## 1. 创建机器人

| # | 操作 | 证据 |
| --- | --- | --- |
| 1.1 | 进入企业微信管理后台 → **工作台** → **智能机器人** → 新建机器人 | [已确认] 62131「第一步：创建机器人」 |
| 1.2 | 填写机器人名称、头像等基础信息并保存（具体字段与校验规则文档未列） | [待界面确认] |
| 1.3 | 保存后进入机器人**详情/编辑页**，记下该页面即为后续配置入口 | [已确认] 62131 / 62154 均指向"机器人配置页" |

## 2. 切换到 API 模式

| # | 操作 | 证据 |
| --- | --- | --- |
| 2.1 | 在机器人编辑页把工作模式从「普通模式」切换为「**API 模式**」 | [已确认] 62131「第二步：开启 API 模式」、62132 |
| 2.2 | 连接方式选择「**长连接**」（不要选"设置接收消息回调地址 / URL 回调"） | [已确认] 62131 / 62154 |
| 2.3 | 保存 | [待界面确认] 具体按钮 |

> 互斥提醒：API 模式只能二选一；切到「设置接收消息回调地址」会使长连接失效，反之亦然。
> `[文档]`（旧版 60904 明写）+ `[待界面确认]`（现行界面是否仍强制）——所以**不要**在长连接模式下
> 再顺手配一个回调 URL。

## 3. 取凭证

| # | 操作 | 证据 |
| --- | --- | --- |
| 3.1 | 在机器人详情页找到 **BotID** 与 **Secret** 并复制 | [已确认] 62131「第三步：获取凭证」、62132 |
| 3.2 | 确认复制的是「长连接」这一行的凭证；不要拿 URL 回调的 `Token` / `EncodingAESKey` 当 Secret | [已确认] 62131 凭证表 |
| 3.3 | 确认该机器人**创建者**是谁（决定 userid 是否加密，见 §0.4） | [已确认] 62155 |

## 4. 交付给工程侧

**[安全]** 凭证只能通过进程环境变量注入，禁止写入仓库、Issue/PR、聊天记录、日志或 `.env` 提交。

```text
WECOM_BOT_ID=<BotID>
WECOM_BOT_SECRET=<Secret>      # 只在部署机的进程环境里
```

- 变量名是本仓库 POC 建议值，尚无实现；t4 落实现时以 ADR 为准。
- 交付方式建议：密码管理器 / 一次性安全通道；不要直接贴在 Issue #13 评论里。
- 泄露处置：控制台重置 Secret（`[待界面确认]` 是否有独立"重置"入口），随后重启服务。

## 7. 配置完成后的自检（工程侧执行，管理员只需配合确认）

| # | 检查 | 期望 |
| --- | --- | --- |
| 7.1 | 服务启动后连 `wss://openws.work.weixin.qq.com` 并发 `aibot_subscribe` | 收到 `errcode: 0`（`[文档]` 62154） |
| 7.2 | 若返回 `853000` | 凭证错/复制错行/Secret 已重置 —— 回 §3（`[实验]` 实测该错误码） |
| 7.3 | 管理员在**手机端**给机器人发一条单聊消息 | 服务端收到 `aibot_msg_callback`，`chattype=single`，`from.userid` 有值 |
| 7.4 | 在一个群里 @机器人 发一条消息 | 服务端收到 `aibot_msg_callback`，`chattype=group`，带 `chatid` |
| 7.5 | 服务停止后重启 | 能重新订阅成功（旧连接会被服务端断开，不要两个进程同时跑） |

## 8. 一次性把"创建机器人"做到可验收的最短路径

1. 确认客户端 ≥4.1.32（0.2）。
2. 决定由超管还是普通管理员创建（0.4）——**建议超管创建**，避免首版就要做 open_userid 转换。
3. 工作台 → 智能机器人 → 新建（1.1–1.2）。
4. 编辑页 → API 模式 → 长连接（2.1–2.3）。
5. 复制 BotID + Secret（3.1–3.2），走安全通道交给工程（§4）。
6. 工程侧自检 7.1–7.2；管理员配合 7.3–7.4 各发一条消息。
7. 把"界面实际存在的可见范围/拉群入口"回填到 §5（当前为 **[待界面确认]**）。
